## Model

A user holds one or more **role bindings**, each scoped to a legal entity, branch or group, with `effective_from` / `effective_to` dates and an approving second person. Roles are never global: a grant only applies inside the scopes the binding covers.

Authorisation is **default deny**. `Authorize(actor, module, action, resource)` must be called by every handler before data is read or written, and `CheckSeparation` must be called with the identities involved in the action. PostgreSQL row-level security then restricts the rows the transaction can see, using the same actor and scope set.

## Separation of duties

Each rule is enforced in the service layer and, where the data model allows it, by a PostgreSQL trigger, so a direct database edit cannot bypass it. A violation is a 403 with the rule id recorded in the audit log.

| Rule | Module / action | Constraint |
|---|---|---|
| `SD-01` | `payments.verify` | A verifier may not verify a submission containing an entry they recorded. |
| `SD-02` | `payments.verify` | A verifier may not verify their own submission or receipt. |
| `SD-03` | `loans.approve` | The approver may not be the applicant or the officer who appraised the application. |
| `SD-04` | `loans.disburse` | Disbursement is confirmed by Finance, independent of the approver. |
| `SD-05` | `loans.review_operations` | Operations review is done by someone other than the appraising officer. |
| `SD-06` | `registration.review_activate` | A group is activated only by a reviewer other than its creator. |
| `SD-07` | `payments.correct` | A correction is authorised by someone other than its requester and the original recorder. |
| `SD-08` | `reconciliation.post` | Posting is confirmed by someone other than the officer who recorded the receipt. |
| `SD-09` | `meetings.amend` | A closed register or minutes are amended only with review by a second person. |
| `SD-10` | `users_roles.grant_role` | Role grants and revocations need a second administrator's approval (four eyes). A second person must approve. |
| `SD-11` | `users_roles.revoke_role` | Role revocations need a second administrator's approval (four eyes). A second person must approve. |

3. `TestSeparationOfDuties` — each rule blocks the actor it names.
4. `TestDocMatchesMatrix` — this document matches the matrix.
5. Route coverage — every non-public HTTP route declares a module and action, and at least one role can perform it.
